# 從 Google 試算表匯入行程 — 設計

日期：2026-08-05

## 問題

使用者在 Google 試算表上規劃行程（欄位：日期／目的地／詳細交通與行程細節／住宿地點／備註／訂票網址／參考資料），改完之後要一格一格複製、貼進 app 的編輯視窗。15 天 × 5 個欄位，每次改動都得重來一次。

## 目標

在 app 裡按一個按鈕就能把試算表的內容拉進來，但**不會覆蓋掉使用者在 app 裡做的調整，除非本人確認**。

## 核心決策

**單向、手動觸發、確認後才套用。**

不做自動同步。使用者明確表示要有確認步驟、不要自動蓋掉 app 上的修改——app 內的編輯（上下移動、日期自動接續、逐日編輯）仍是完整可用的功能，匯入只是一個「把試算表的內容拉過來」的動作。

**不經由 Firebase 中轉。** 曾評估用 Google Apps Script 把試算表寫進 Firebase，但那需要資料庫密鑰、觸發器，多了兩個失效點，而且本質上是自動同步（與上述決策衝突）。Firebase 的官方作法 Cloud Functions 需要 Blaze 付費方案，本專案是 Spark 免費方案。

## 技術前提（已實測）

**瀏覽器可以直接抓 Google 試算表的 CSV。** 測試 `https://docs.google.com/spreadsheets/d/<ID>/export?format=csv&gid=<GID>` 帶 `Origin: https://raycm.github.io`：

```
HTTP/2 307
access-control-allow-origin: https://raycm.github.io
HTTP/2 200
access-control-allow-origin: *
```

307 轉址與最終回應都帶 CORS 標頭，所以 `fetch()` 不會被擋。不需要 API 金鑰、不需要 Apps Script、不需要後端代理。

前提是試算表維持「知道連結的人皆可檢視」。改成私人就會 403。

**日期格式不需特別處理。** 試算表的 `10/21(週三)` 用 app 現有的 `parseMD()` 就能解析——實測 15 列全數正確。

**必須用正規的 CSV 解析器。** 儲存格內含逗號與換行（例如 10/23 的備註是一段多行文字），用 `split(',')` / `split('\n')` 會把整份資料拆爛。實測過，不是理論風險。

## 改動內容

### 1. 入口

編輯模式下，「＋ 新增一天」按鈕旁邊新增「⇩ 從試算表更新」。非編輯模式不顯示。

編輯模式本身已經有 `dbRef && !dataLoaded` 的防護（資料未載入完成時不能進入編輯），因此匯入不會在資料還沒載入時發生。

### 2. 抓取

試算表 ID 與 gid 直接寫在 `index.html` 的常數裡。它是公開連結，不是祕密，不需要進 `config.js`（那個檔是 GitHub Actions 從 secrets 產生的，為此多開一個 secret 不划算）。

抓取失敗（無網路、試算表改為私人、Google 服務異常）時顯示錯誤訊息並中止，**行程資料一個字都不動**。

### 3. CSV 解析

自行實作一支解析器，需正確處理：
- 引號包住的儲存格
- 儲存格內的逗號
- 儲存格內的換行
- 跳脫的雙引號（`""`）

### 4. 欄位對應

| 試算表欄位 | app 欄位 | 匯入行為 |
|---|---|---|
| 日期 | `date` | 用於配對，不覆蓋 |
| 目的地 | `dest` | 覆蓋 |
| 詳細交通與行程細節 | `trans` | 覆蓋 |
| 住宿地點 | `stay` | 覆蓋 |
| 備註 | `note` | 覆蓋 |
| 訂票網址 | `url` | 覆蓋 |
| 參考資料 | — | 忽略 |
| — | `leaf` | 保留 |
| — | `r` | 保留 |
| — | `stayUrl` | 保留 |
| — | `ulabel` | 見下 |

**`ulabel`（訂票按鈕文字）**：`url` 有變動時清空 `ulabel`，讓按鈕退回通用文字。網址換了而標籤仍寫「JR e5489 訂票」會誤導使用者。此變動要列在差異清單中。

`url` 未變動時 `ulabel` 保留不動。

**空白儲存格視為空值**，會覆蓋掉 app 上的既有內容（試算表清空某格＝有意刪除該欄）。這一點要在差異清單中明確顯示為「刪除」。

### 5. 配對規則

依日期配對，用 `parseMD()` 把兩邊的日期正規化成 `MM/DD` 之後比對。順序不影響配對。

| 情況 | 行為 |
|---|---|
| 兩邊都有這個日期 | 逐欄比對，只列出真的有差異的欄位 |
| 試算表有、app 沒有 | 標示「新增這天」，預設**不勾選**，使用者勾了才加 |
| app 有、試算表沒有 | 標示「試算表沒有這天」，**絕不刪除**，僅告知 |
| 試算表某列日期無法解析 | 略過該列，在差異清單中告知第幾列被略過 |
| 試算表出現重複日期 | 以最後一列為準，並在差異清單中告知 |

### 6. 差異預覽

跳出視窗列出所有變動，每一項可個別勾選（預設：既有天的欄位變動勾選、新增天不勾選）。使用者按「套用」才執行。

沒有任何差異時顯示「試算表與目前行程一致」，不進入套用流程。

### 7. 套用

1. 依勾選項目修改 `itinerary`
2. 呼叫 `resequenceDates()`（新增天之後日期需重新連續化）
3. `pushField('itinerary', itinerary)` 寫回 Firebase
4. `renderTimeline()` 重繪

所有裝置會透過 Firebase 的即時監聽同步看到。

## 測試方式

專案的測試在 `tests/`，作法是從 `index.html` 原始碼抽函式出來 eval（見 `tests/README.md`）。本功能沿用同樣作法，新增 `tests/test-sheet-import.js`：

- CSV 解析器：引號、逗號、換行、跳脫雙引號、空儲存格、CRLF
- 配對：日期正規化、順序不同仍能配對、試算表多一天、app 多一天、重複日期、無法解析的日期
- 差異計算：無變動時回空、只列出真的有差異的欄位、空儲存格視為刪除
- 欄位保留：`leaf` / `r` / `stayUrl` 在匯入後不變
- `ulabel`：`url` 變動時清空、`url` 未變動時保留
- 套用：只套用被勾選的項目、套用後日期仍連續

另外把實際的試算表 CSV 存一份當 fixture（`tests/fixtures/sheet-sample.csv`），確保解析器對真實資料有效，且日後試算表格式若變動能被測出來。

## 範圍外

- **不做自動檢查更新**：開啟 app 時不會背景抓試算表比對。避免無網路時的干擾與每次載入的額外請求，代價是使用者要記得按按鈕。
- **不做反向同步**：app → 試算表不在範圍內。
- **參考資料欄不匯入**：app 沒有對應概念。要支援的話需新增一個欄位與一個連結按鈕，屬於另一個功能。
- **不支援多個工作表**：只讀 `gid=78477160` 這一個分頁。
- **試算表分享權限改變時無法自動偵測**：只會在抓取時失敗並顯示錯誤。
