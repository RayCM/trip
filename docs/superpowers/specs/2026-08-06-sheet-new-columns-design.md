# 試算表新增欄位：雨天備案、參考資料 — 設計

日期：2026-08-06

## 問題

試算表新增了「雨天備案」欄，加上先前就存在、但匯入功能沒納入的「參考資料」欄，目前 app 讀不到這兩欄——`SHEET_COLS` 沒列到的標題會被靜默忽略。

試算表現況（15 天）：

| 欄位 | 有值天數 | 型態 |
|---|---|---|
| 雨天備案 | 14/15 | 長段文字，多行 |
| 參考資料 | 1/15 | 網址 |

兩欄的資料型態不同，需要不同的呈現形狀。

## 核心決策

**明確定義這兩欄，不做泛用的動態欄位機制。**

曾評估「app 讀到不認識的標題就自動多一列」。否決的理由是它做不到最重要的事：沒有任何通用機制能判斷某欄該當純文字還是當連結——參考資料會變成一串裸網址而不是可點的按鈕。而且試算表上任何人隨手加的暫存欄都會直接跑到行程卡片上。

改為：兩欄各自明確定義，另外在差異確認視窗底部列出 app 不認識的試算表標題。使用者未來加欄時會被告知，而不是像現在這樣完全無感。

**兩欄都可在 app 的編輯視窗修改**，與現有六欄行為一致：在 app 改過之後，下次匯入會把它當成差異讓使用者確認，不會默默覆蓋。

## 選用欄的語意（唯一的架構改動）

現行 `SHEET_COLS` 六欄全為必要：任一標題找不到就中止整個匯入（`index.html:819-820`）。那是刻意的保護——把缺欄當空值會對每一天產生一筆「清空」差異且預設勾選，整欄被抹掉。

新兩欄不適用同一規則。參考資料 14/15 天空白，且兩欄都是近期才加的，未來可能改名或移除。設成必要欄的話，刪掉一個幾乎沒在用的欄位就會讓整個匯入失效。

引入第三個元素作為選用標記：

```js
const SHEET_COLS=[['date','日期'],['dest','目的地'],['trans','詳細交通與行程細節'],
 ['stay','住宿地點'],['note','備註'],['url','訂票網址'],
 ['rain','雨天備案',true],['ref','參考資料',true]];  // true = 選用
```

- **必要欄缺席** → 進 `missingCols`，中止匯入（維持現狀）
- **選用欄缺席** → 不進 `missingCols`，且 `diffSheet` **完全跳過該欄位**

第二點的後半是關鍵，不能退化成「當作空字串」——那正是上述資料損毀路徑。實作上 `sheetRowsToDays` 需回傳本次實際存在的欄位集合，`diffSheet` 依此決定要比對哪些欄位。

這是整份改動中唯一的結構性變化。

## 編輯視窗改為 merge

`saveDayForm`（`index.html:994`）目前是 `itinerary[editingIndex]=day`，整包覆蓋。表單重建的 day 物件只含表單裡的欄位，所以任何不在表單中的欄位都會在使用者編輯該天時被靜默丟掉。

改為以現有 day 為基底 merge。表單管理的欄位語意不變（留空即刪除該欄），未列在表單中的欄位則保留。

這順帶消除一個現存風險：往後再新增欄位時，不會因為忘了同步表單而丟資料。

## 改動清單

**欄位定義**
- `SHEET_COLS`（810-811）：加兩欄與選用標記
- `sheetRowsToDays`（812-833）：選用欄缺席不中止；回傳本次存在的欄位集合；day 物件加 `rain`、`ref`
- `diffSheet`（836-853）：接收欄位集合，跳過缺席的選用欄
- `SHEET_FIELDS`（834）、`DIFF_LABEL`（884）：加兩欄，否則永不被比對

**卡片渲染（715-729）**
- 雨天備案：仿 `note` 的空值守衛與列結構，☂ 圖示
- 參考資料：仿訂票按鈕，`📖 參考資料 ↗`
- 兩者都需空值守衛——參考資料 14/15 天為空，不得渲染空列或空按鈕

**編輯視窗**
- HTML（374 附近）：雨天備案 textarea、參考資料 input
- `openDayForm`（956-961）：填入現值
- `saveDayForm`（988-994）：收集兩欄、空值刪除、改為 merge

**差異視窗**
- `renderSheetDiff`（901-）：底部列出 app 未使用的試算表標題

**測試**
- `tests/fixtures/sheet-sample.csv`：加兩欄標題與資料
- 選用欄缺席時不產生任何清空差異（最關鍵的一條）
- 兩欄的 diff 與套用
- 編輯存檔保留未列在表單中的欄位
- 卡片對空值不渲染

## 不做

- 泛用動態欄位（理由見核心決策）
- 多工作表支援（延續原設計的限制）
- 未知欄位除了「告知」以外的任何處理
